# Hatch visual and workflow review

Review date: 2026-10-03  
Reference: `DESIGN.md` and the accepted decisions in `DECISIONS.md`  
Method: disposable in-memory project, 21 synthetic tickets spanning all 16 statuses and all four turn colors, proposal and sketch data, a question with answers, Specs, decision, previews, worktrees, agent runs, and successful and failed sync entries. The snapshot harness ran every captured route in light and dark appearance. It writes screenshots to `/tmp/hatch-view-audit-v9/` and does not use the Hatch database or probe GitHub/Claude credentials.

## Cross-screen findings

- The live application screenshot shows the selected sidebar row as a normal blue system selection. The bitmap snapshots show a black sidebar column, so that black area is a capture artifact and must not be “fixed” in the app.
- Light and dark appearances keep the system typography and status colors readable. Active turns use amber or teal; neutral metadata stays subdued. The embedded sketch sample has its own light background in both modes, as expected for the fixed CSS in that HTML fixture.
- The toolbar uses icon-only Search, New Ticket and Ask controls with shortcut help. The project selector was a custom button and popover despite the design rule calling for a native menu. This review changed it to SwiftUI `Menu`, with the project name and tile retained in its label and checkmarks identifying the selection. Local Xcode build passed after the change.
- The route screenshots use realistic, but synthetic, records. No private ticket contents were read into the fixtures and no GitHub writes occur in snapshot mode.
- The command-palette capture uses a demo-only presentation of the sheet's contents; it does not show the dimmed parent window. The Ask panel capture uses its normal side-by-side layout with a demo-only presentation flag.
