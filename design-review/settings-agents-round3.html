2. Models for coding agents

The honest answer today: Hatch does not start coding agents yet. You start the program (Claude Code), it calls hatch take, and it uses whatever model the program defaults to. So Hatch does not choose at all. Once Hatch starts agents itself, it should pass the model. These are the ways it could be chosen.

A · RECOMMENDED: CODING WORK AS TASKS
Prepare optionsOpus 5.5, high effort
BuildSonnet 5.5
Fix after reviewSonnet 5.5
Plan large changesOpus 5.5

The kinds of agent work Hatch already knows (Prepare, Build, Fix, Plan) become tasks in the same list as Iris and Ask, with the same default and the same sheet. One place, one way to choose. Hatch passes the model when it starts the agent. "Agents at once" stays.

B · ONE MODEL FOR ALL CODING
Run agents withOpus 5.5 · Claude Code

Simplest: every coding agent uses the same model. Wastes Opus on small fixes, or Sonnet on hard proposals.

C · HATCH CHOOSES BY SIZE
Choose the model for each ticket

Rules Hatch can apply from what it knows: a Tweak or a plan under 8 files gets Sonnet, a Proposal or a large plan gets Opus. The rule is shown on the ticket, and you can override it. Deterministic, so it does choose the right model by its rules, not by guessing.

D · START SMALL, STEP UP
Step up after failed builds2

Every agent starts on the cheaper model; if its build or tests fail twice, Hatch restarts it on the stronger one. Saves the most, costs time on hard tickets. Combines with A or C.
