Agents page: round two

Five things you pointed out, each with a few ways to solve it and my recommendation. One rule comes out of them for every page: a row holds a label and one value or control, never a value plus a button. Buttons go in a section's header or below a list, and results show as status, not as extra rows.

1. Test and its result

Today: a Test button in each section header and a "Last test" row that appears afterwards. The button is easy to miss, the row changes the layout, and nothing says whether the task works until you test it.

A · RECOMMENDED: CHECKED FOR YOU
Check new ticketsReady · Haiku 4.5 answered in 1.7 s
›

Hatch sends one short test whenever a task's provider or model changes, and once a day. The result is the task's status line: a green dot when it works, red with the reason when it doesn't. "Test Again" lives in the task's sheet for when you want it.

B · ONE BUTTON FOR THE PAGE
Test All
Check new tickets1.7 s

You test on purpose, all tasks at once; each row shows its result. Nothing runs without you asking.

C · IN THE CONTEXT MENU
Test Check new tickets
Show Last Result

Right-click a task to test it; the result appears as its status. Hidden until you know it is there.
