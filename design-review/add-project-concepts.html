What a project is made of, three ways to set one up, and the details you asked about: fields, GitHub, the app folder, Hatch's branch and what each repository is. Each part has one recommendation. The questions at the bottom are what I need from you.

What a project is made of

These pieces work together; none of them replaces another. The app folder is not an alternative to GitHub: it is your clone of the same app repository, on this Mac, where agents build and test.

⌥

GitHub account

Who Hatch acts as. Set up once for the whole app, not per project. Hatch only sees repositories its GitHub App is installed on.

#

Tickets required

A private repository whose Issues are your tickets. One for all projects, so ticket numbers never clash. Hatch can create it.

{}

App code required

The repository agents change (tashda/echo), plus your clone of it on this Mac. Agents work in their own copies of that clone (git worktrees) and never touch your working files.

◐

Design system optional

The package with your colors, type and components. Proposals are built against it so previews look like the real app. Skip it if the design system lives inside the app.

⑂

Hatch's branch

Approved work collects on a hatch branch. CI checks it, then it moves to your base branch (dev). Your base branch never gets an untested merge.

◫

Specimens automatic

Where Proposal code lives (echo-specimens). Hatch creates it when the first Proposal needs it, so it is not part of setup.

Three ways to set up a project

All three use the same smart defaults: the name comes from the app repository, the key comes from the name, the folder is found on this Mac, and the base branch is the repository's default branch.

Recommended

A · Setup assistant

One sheet, with the steps listed on the left. Each step asks one thing, explains it, shows an example and is already filled in, so most steps are only Continue. It explains each part the first time you see it, without a manual.

B · One page of cards

A single scrolling sheet with one card per part, each with its explanation and a picker. Faster for someone who already knows Hatch, but it is a lot at once on first run. I suggest this layout for Project settings, where you edit an existing project.

C · Start from the app repository

Pick tashda/echo. Hatch fills in everything else and shows a summary with a Change button on each row. The fastest option, but it teaches nothing, so a design repository or the branch flow stays a mystery.

A · Setup assistant (click the steps)

Native fields with no white boxes, every repository chosen inline, and an example on each step.
